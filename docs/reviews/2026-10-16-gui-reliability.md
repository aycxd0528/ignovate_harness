# GUI 代码显示、等待队列与旧会话恢复

## 修复内容

1. Markdown 渲染原先只保存代码块语言标签，没有执行语法高亮。现使用随包分发的 highlight.js 11.11.1 常用语言构建，先清理 Markdown 再高亮纯代码；未知语言不自动猜测。浅色、深色和系统主题均有配色。代码字体优先使用 Consolas / Cascadia Mono，14px、1.65 行高，复制仍保留原文。
2. 等待消息原先只有底部移除入口，没有编辑入口，移除还会暂停执行队列。现于输入框上方显示当前会话队列，支持编辑、保存、取消及独立删除；保留模式和顺序。开始执行后的请求拒绝修改，过期编辑不能覆盖较新的内容，后台刷新及迟到的保存响应不会丢弃正在编辑的文字。
3. 导入历史一律设置为 legacy，界面因此禁用发送；执行端还会拒绝所有 legacy，包括实际仍有终态检查点的会话。现独立核对当前会话能否继续：末轮输入、最终回答、时间或回合标识须与持久化终态 checkpoint 一致，且无待执行步骤和未闭合工具。继续沿用原 thread，不为旧节点补造精确分叉绑定；发送及执行前再次核对。
4. 部分异常（如无文字的 TimeoutError）此前被存成空字符串，界面只显示“失败”。现保留异常类型、有限原因链及可用的 HTTP 状态和请求标识，展示前脱敏，并可复制运行标识、时间、用时及错误详情。

## 闲置故障的调查边界

用户报告 Windows / macOS 长时间闲置后发起请求，约 9 秒后失败，重启后恢复。本机没有对应当天的失败记录，尚未复现底层异常，不能认定是连接池、网络或数据库问题。此次已修复错误原因丢失，未增加整轮自动重放或未经验证的连接轮换。若再次发生，可使用“复制错误详情”取得诊断信息。
