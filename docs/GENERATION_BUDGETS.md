# 生成额度、截断恢复与会话预算

本次调整来自 A–F 日志扫描缓存任务的轨迹复核。历史 Agent F 的收尾响应达到输出上限而没有正文，且实验控制器的累计预算无法约束原生调用。这里分别处理生成、结束状态、用量结算与累计准入；这些机制不保证模型能完成任务。

## 生成额度

主模型显式传入 `max_tokens`。当前 Harness 策略对 `deepseek-flash`、`deepseek-v4-flash`、`deepseek-v4-pro` 使用以下默认额度；这是客户端选择的额度，不是对提供商模型身份或最大能力的声明。

| 推理配置 | 默认输出额度 |
| --- | ---: |
| `max` | 131,072 |
| `default`、`high`、`low`（开启推理） | 65,536 |
| `none`（关闭推理） | 8,192 |
| 其他模型别名 | 4,096 |

这些默认值来自 [DeepSeek 当前接口说明](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)。服务端最大输出 393,216 与默认额度是不同概念；别名或服务端模型版本仍需单独记录。项目显式配置优先于默认值。

额度同时容纳推理与正文。上下文窗口不足时仍会裁剪，`context_request` 事件记录 `requested_output_tokens`、实际 `output_reserve` 和 `output_clipped`。改变模型或推理配置会重新构造模型并更新生成额度。

普通项目可在 `.nailong/settings.json` 配置；`.nailong/settings.local.json` 中同名字段覆盖前者：

```json
{
  "generation": {
    "max_output_tokens": 32768,
    "max_truncation_retries": 1
  },
  "budgets": {
    "session_token_limit": 120000
  }
}
```

输出额度必须是正整数，恢复次数只能为整数 `0` 或 `1`。非法配置在请求之前报错。子任务沿用其独立额度，不自动重复截断调用。

## 截断与交付状态

`model_response` 记录唯一调用 ID、`finish_reason`、正文长度、请求额度、已知推理用量和 input/output 用量。子任务使用 `subagent_model_response`。新增诊断事件不保存原始思考文本；提供商协议要求的 `reasoning_content` 仍保留在正常会话与实际请求中。

主模型遇到 `finish_reason=length`，最多追加一次带截断响应与继续指令的新请求，并重新进行全部预算检查。截断的工具参数不会执行。连续截断、空续答、恢复异常、调用次数不足或累计余额不足都会停止；已观察到的响应仍结算用量。

服务在无法恢复时保留任务与产物，输出可见提示、诊断和 `output_status=truncated`；预算拒绝则为 `budget_stopped`。任务交付保持 `unverified`，不会因为收到了模型响应就被认定完成。恢复成功的最终事件含恢复标记，首次隐藏响应和续答的用量各入账一次。

## 累计会话预算

默认不开启累计 token 限制。配置 `budgets.session_token_limit` 后，同一会话的主模型、子模型和恢复请求共享累计账本；单轮 `max_model_calls`、子任务额度、费用预算和上下文窗口继续独立生效。

需要严格预留的普通执行器可通过构造参数开启预算，避免为配置修改题目工作区：

```python
factory = AgentRuntimeFactory(
    settings,
    session_store=session_store,
    session_token_limit=120000,
)
```

该参数优先于项目配置。累计账本位于会话数据根目录的 `token-budgets/<会话ID的SHA-256>.json`，不放在代码工作区。预算使用整个会话的 input + output，缓存命中已经包含在 input 中，推理用量已经包含在 output 中，均不再重复相加。账户收费与本预算是不同口径。

上述示例同时显式降低输出额度到 32,768。在默认 `max` 的 131,072 输出额度下，严格 120,000 预算会拒绝首请求；普通项目应根据所需输出额度配置可容纳输入与输出预留的预算。

历史 INCACHE-1.1 的 Agent F 操作端协议采用另一种边界：新调用开始前检查已回传用量是否达到 120,000，允许已准入调用完成后超出限额。相同条件重测必须保持这条规则，关闭原生严格账本，由操作端按真实回传用量计数；不能把严格预留改动混入预算相同的结论。两种准入规则分别记录，不相互替代。

每次请求预留完整输出额度与保守输入上界；余额不够即拒绝发送，不自动缩小为几乎无法生成正文的额度。原生 DeepSeek 请求通过同一 SDK 的消息与工具序列化计算 UTF-8 字节上界，加固定封装余量，排除不会发送的内部调试、用量和来源元数据，保留真实 reasoning 字段。其他模型使用通用保守序列化。这个上界不是精确 tokenizer，可能较早拒绝请求。

已知用量按提供商回传 input + output 结算。缺失用量、已发送请求的异常或取消会按预留额度保守结算并停止后续调用；请求在发送前失败可释放预留。启用预算时关闭原生 SDK 的隐藏重试，每次物理请求有对应账目。恢复一次是显式的新调用。

账本原子发布，持有跨进程文件锁。重启保留已花费用量；未结算请求按未知用量处理并停止；损坏账本、并发持有、限额改变会拒绝继续。回退会话或删除预算配置都不会退回已消耗资源，也不会禁用已经持久化的账本。更改固定实验限额需要另建会话。

## 预算压力下的请求视图

累计预算不足以容纳下一次完整请求时，可以对较早已完成的工具结果做 L1 压缩。仅在实际可用工具包含 `read_history_result` 且归档完整时应用；当前用户输入、系统约束、最近一组工具结果、未完成工具调用和 required reasoning 保留。归档正文截断时不应用候选。

这里仅改变发送给模型的请求视图，检查点保留原文。只有压缩后确实能容纳完整输入与输出预留才应用；`budget_compact` 事件记录前后上界、余额、是否应用与失败原因。压缩不替代精确 token 计数，也不保证模型会停止继续探索。

## 请求重复与阶段约束

系统提示合并重复指导，保留当前权限、工具能力、来源与证据边界。计划阶段按当前有效约束交付方案和未确定项；后续阶段尚未授权的实施决策不阻止独立调查结果的交付。

技能目录保留全部启用技能的名称与来源，长描述显式标记摘录，实际 JSON 转义后的目录保持字符上限；`load_skill` 仍读取完整原文。任务投影仅以请求内索引替换逐字相同、完整可见的用户要求，原消息、要求状态和完整归档均保留。压缩移走旧用户消息后，必须先重建投影和恢复有效要求，再估算请求与生成检查点；不能沿用压缩前的索引。

## 验证与已知边界

离线测试覆盖真实 SDK 载荷、SSE 截断后续答、HTTP 失败不隐藏重试、跨轮与重启结算、并发预留、未知用量、上下文和截断归档边界。完整原生回归通过才可同步实现。

2026-10-10 第一批工程 API 验证使用 `deepseek-flash`、`max` 与严格 120,000 累计额度，在临时题目目录运行原 R1。四组最多八次调用的变体因保守准入停止；限制四次调用的变体，最后一条响应仍以全部 32,768 输出额度用于推理而截断，未产生计划正文。其白名单还用了未注册的 `list_directory`、`search_files`，实际缺少目录与搜索工具；原实验提供完整工具集及 40 次调用。上述结果仅是工程探针，不能作为相同条件重测证据。

第二批恢复原生工具集、每轮 40 次调用和原操作端预算边界，并对齐提供商的生成默认额度。离线回归验证额度传播、切换、窗口裁剪、恢复与用量结算；真实交付以另建 run 的产物、快照与操作端评分为准。现有流式视图可能先显示截断片段再显示完整替代正文；最终事件有恢复标记，交互视图的显式替换边界仍可改进。正式比较须冻结模型身份、各类调用配置、预算与权限，保留所有历史失败与成绩。

完整工具集的两个 R1 工程探针分别消耗 130292 和 147045 tokens，均按原操作端边界停止，尚未交付。请求精简减少了首请求输入组成，但没有证明模型推理消耗下降或交付成功。最终候选须分别接受 120000 tokens 原协议重测；用户在 2026-10-10 另行授权 3000000 tokens 六轮交付实验，该实验只检验额外资源下的交付能力，不计为相同预算改善。
