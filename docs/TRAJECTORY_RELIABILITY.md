# 工具轨迹与交付证据

每个真实用户回合有独立 turn_id。tool_start 表示模型请求，execution_state=requested；tool_end 的 started 由执行入口报告。handler 开始执行不等于子进程启动、测试执行或功能验收通过。缺少执行状态的旧适配器显示 unknown。历史图消息重复投影记录为 history_replayed，不再次计入本轮请求、不触发观察器或 PostToolUse。新的 AI 消息合法复用旧 call_id 仍作为新请求。原生执行入口生成 tool_result_id，覆盖handler同名字段，并随归档保留；同一个结果即使消息ID被重写仍可识别。此身份不是执行成功的证明；任务证据也按结果身份记录。旧第三方适配器没有运行时结果身份且改写消息ID时，无法充分区分旧结果和同call_id的新结果；显示 message_identity_only，不能把去重覆盖声明扩大到该情况，不能依靠输出文本去重。

单个验证程序优先使用 run_command(argv=[...])，直接启动参数数组，command 与 argv 只选一种。expected_exit_code 默认为 0；结果保留实际 exit_code、匹配状态、完成/超时/取消及执行模式。shell 字符串保留兼容行为；后续 echo 的零退出码无法证明前面的测试成功。输出摘要是观察资料，不能证明测试实际执行。output_archive 提供分页引用与完整性；达到原有归档上限时明确标为不完整。审批绑定原参数，Bash 规则按 argv 的可解释展示匹配；直接执行不扩大权限。

明确的用户阶段限制由受信任 TaskStore 用户要求编译，执行前和审批后重新核对。模型 phase、文档和工具输出不能授权。策略识别明确的阶段标签、字面命令/脚本与后续用户明确目标授权/解除指令；未知阶段显示 unknown 并保留受限目标。后续“现在执行”按明确参数放行，--dry-run不能授权--publish；不要求用户说特定解除口令。任意动态程序、变量展开和间接启动行为无法由这套有限语法完全判定，它不是操作系统沙箱。对于复杂限制应使用明确的工具/argv 契约与隔离运行环境。

原生批次对同一规范文件路径的多次 write_file/edit_file 在审批前返回 batch_file_conflict，所有冲突成员均未启动。独立文件按原版本审批。多处修改合成一次完整补丁，或在下一个批次重新读取；不能自动重基或用覆盖规避版本检查。

context.history_input_target_tokens（默认 150000）是请求历史偏好，不是累计 token 上限。仅当完整归档和 read_history_result 均可用时，较早已闭合用户回合可改为包含证据索引的摘要。当前真实用户回合的整条工具链及 provider reasoning 保留，原 checkpoint 不变；归档截断或无法恢复时保留原文。实际费用和任务表现的改善须另行同条件复测。

运行时事实包括 Harness 解释器、版本、平台、临时目录与本会话 active goal 状态。Harness 解释器不一定是被测项目解释器，环境路径也不表示访问授权。交付文档中的行为描述须核对实际代码或最终版本的测试，未测内容标为推断或未知。

## 固定源码复测

复测从独立冻结目录启动，记录源码文件清单与 SHA-256、依赖锁文件、模型/推理配置、题目与工具目录；每轮和结束核对同一清单。当前 GUI 开发目录只作为独立状态记录，不能用其后续变化否定或证明另一个冻结版本。原始审计保留；范围审计明确覆盖与未覆盖部分。原生轨迹、模型调用身份、工具消息和产物快照一并保存，历史回放与真实请求分别统计。
