# 自动记忆提取与向量索引评估

本次用户目标先要求会话隔离、截断可见、记忆目录、按需读取和统一预算。这些能力已提供可追踪的文件版本与分页接口；自动提取和向量数据库作为下一阶段决策评估，本次不引入新服务或写入行为。

参考 [CL4R1T4S 的 memory 内容](https://github.com/elder-plinius/CL4R1T4S/blob/main/ANTHROPIC/CLAUDE-OPUS-5.5.md) 中可迁移的方向：简短的常驻记忆、目录与按需加载、把稳定事实和临时会话状态分开。这是社区材料，用于设计参考，不作为官方产品规格或运行指令。

## 自动提取

现阶段保留用户显式编辑。项目还没有事实正确率、重复率、冲突率的评估，也没有逐条事实的来源、撤回和生命周期管理；直接从所有对话自动保存会混入助手猜测、过期任务进度和用户未确认的内容。

建议先实现可审阅的候选流程：仅从用户明确说明或有工具证据的稳定事实生成候选，标记来源会话、证据、作用域、创建时间和替代关系；默认显示差异，由用户选择保存、忽略或撤回。临时任务状态继续留在会话与历史归档；项目事实存项目层，个人偏好存用户层，本机路径存本地层。沿用现有版本冲突检查及原子写入。

开始实现前，用人工标注会话集衡量事实正确率、作用域准确率、重复及冲突率、敏感信息误保存率、用户拒绝率和新增调用费用。经用户验证候选流程有价值，再讨论显式启用的自动保存策略。

## 向量数据库

当前主题目录上限 200，结构化描述与精确 ID 已支持确定性发现和完整分页读取，没有检索评估证明需要向量服务。现在引入会增加嵌入成本、索引更新、删除同步和数据作用域隔离的维护成本；它也不能替代上下文预算或文件版本检查。

先用真实问题建立“问题 → 应读主题”的评估集，记录目录检索的命中率、完整证据召回、读取次数、延迟和模型输入成本。若主题规模持续增长或语义相似的问题经常漏掉已存在资料，先比较文件名/描述/正文关键词搜索，再与嵌入检索比较。

只有测量结果显示语义检索能改善召回且费用和延迟可接受时才添加索引。可从本地索引起步，以原文件为事实来源；索引记录作用域、文档 ID、内容版本、片段偏移，过滤当前项目和权限后再检索，文件变更或删除时更新索引。取回正文仍经过现有分页和统一预算接口，不直接把全部匹配片段注入提示词。

## 本次结论

基础记忆能力先落地；自动提取的下一步是可审阅候选与评估集，向量索引的下一步是检索质量测量。两项都没有自动开启，也没有迁移现有文件。
