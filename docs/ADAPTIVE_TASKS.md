# 普通会话、持续任务和协调

普通会话按需加载能力。独立问候不绑定工具，一般交流先提供工具发现和 Skill 搜索；工具被发现后，从下一次模型请求起可用。Skill 搜索返回元数据，正文仍需按名称加载。显式模式、allowed_tools、权限、审批及阶段限制继续生效。

用量详情区分本轮实际输入、输出、缓存命中与会话累计；缓存是输入的子集。分类项来自请求估算，不能当成提供商实际分项账单。旧记录缺少用量或价格时显示未知；相同 model_call_id 的重复记录只计算一次。

## 在同一会话持续完成任务

直接描述想达到的效果即可。模型可以用 `prepare_task` 保存目标、范围、约束、验收和关键疑问。核心会显示带版本的草案；疑问未解决时不能开始。用户说“按这个做”“开始实施”后，`start_task` 提交启动意图，原生目标驱动器在当前模型轮结束后推进。已经清晰授权的直接实施请求也可在本轮准备并启动。

草案中的 `verification` 使用现有验证步骤格式。自动验收必须明确关联步骤和覆盖路径，例如：

```json
{
  "objective": "修复计算结果",
  "scope": ["calc.py", "tests/test_calc.py"],
  "constraints": ["保留现有公共接口"],
  "open_questions": [],
  "acceptance": [
    {"description": "边界输入结果正确", "step": "calc", "paths": ["calc.py", "tests/test_calc.py"]}
  ],
  "verification": [
    {"name": "calc", "kind": "test", "command": "python -m unittest tests.test_calc", "timeout_seconds": 30}
  ]
}
```

简单字符串验收需要人工确认，模型不能代签。验证命令仍通过原有权限和原生审批。没有有效目标验收和当前输入的原生验证证据时，任务保持未验证。原有 `/plan`、`/goal` 和 `/task` 继续可用。

说“暂停任务”可暂停自然启动的持续任务；说“继续执行”可恢复原目标。已用成本与轮数不会清零。达到总上限仍需明确调整或建立后续目标，不能通过子任务续作绕过。

## 子 agent 的阶段预算

在 `.nailong/settings.json` 或 `.nailong/settings.local.json` 配置：

```json
{
  "subagents": {
    "max_concurrency": 3,
    "stage_tokens": 30000,
    "output_tokens": 4096,
    "final_output_tokens": 1024
  }
}
```

并发为 1–3；阶段总额度为 4096–2000000；输出为 128–131072；收尾输出为 128–16384。实际输出继续受模型、上下文窗口及阶段剩余额度限制。修改配置后重建运行时生效。

`task(description, resume_reference)` 返回结构化状态、原生读取证据、未完成项、停止原因和续作引用。预算耗尽或取消会保存已结算的阶段，后续父轮可携带引用继续。父任务修订或输入变化时拒绝直接复用，要求重新核对。未知 usage 不冒充完成；旧字符串 worker 不会获得伪造证据。子 agent 仍然只读。

## 协调已有会话

在当前目标中明确要求“协调/接管已有会话”，按需发现 `session` 工具组：

- `list_task_sessions`：有界任务摘要；`read_session_history`：定向分页历史。
- `take_session`：检查目标任务修订、范围、可接续 checkpoint 和当前控制权。
- `dispatch_session`：只提交派发；唯一 request_id 使重试幂等；依赖必须指向已有派发。
- `coordination_status`：读取原生结果和交付状态；`pause_coordination`：暂停或释放一个会话，空会话参数操作该来源的全部会话。

共享外层驱动器串行消费派发，复用目标会话已有上下文、文件版本检查和审批，不创建可写子 agent。目标会话保持自己的 task_id；总目标的归属不会切换到执行会话。局部文件范围不允许运行无法证明范围的命令。

派发 `completed` 表示该执行轮已收束；结果中的 `delivery` 才描述目标验收。整体完成仍需协调目标自身的集成验证，不能累计几个模型“完成”报告就交付。

用户在被接管会话输入新的实质指令，会作废旧控制版本。恢复时，确定未启动的排队项可继续；admitted/running 必须核对原生回执与费用结算。缺少证据的状态保留为 `needs_reconciliation`，不自动重放文件写入或命令，也不自动解除用户暂停。

每个项目最多保留 200 个子任务阶段、200 条派发，状态文件另有大小上限。达到上限会明确停止保存新工作，现有记录保留。
