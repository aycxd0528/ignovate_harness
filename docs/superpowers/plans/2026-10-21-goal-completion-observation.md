# 目标完成检查的并发与取消修复

**目标：** 大项目摘要扫描期间，状态读取和用户暂停保持可用；旧观察不能覆盖任务、目标、验证或协调控制的新状态。

**设计：** 同步 API 保留。完成检查先在事务外取得完整 Goal/Task 快照及输入摘要，再按 Task → Goal 顺序进入短事务，逐项重核后提交。原生派发 admission 与完成检查共用 Goal 事务，派发不能在目标完成后发布陈旧 active 观察。原生异步 update_goal 复用可取消的摘要 worker，取消后等待在途读取清理并拒绝提交。

## 约束

- 保留当前工作区及用户已有修改，不提交、不推送。
- 不放松输入覆盖、实际验证、任务验收、费用及未完成派发的完成门槛。
- 扫描期间不持 Task/Goal 事务锁；合并操作统一 Task → Goal 顺序。
- 旧检查不得清除等待期间新产生的验证证明，不自动解除用户暂停。
- 取消只等待已经在途的文件读取，不继续扫描后续块；不承诺中断操作系统内阻塞的文件调用。
