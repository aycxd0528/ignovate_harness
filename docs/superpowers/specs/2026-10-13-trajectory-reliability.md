# 工具轨迹可靠性与执行效率

依据：用户已审阅run-008优化清单并要求“开始修改”。目标是修正历史回放、阶段限制、验证结果、编辑冲突及上下文开销，保留既有GUI和已测V4。实现从当前工作树792个文件的稳定副本开始；基线1360测试/43跳过/1317执行通过，exit0。

1. **事件真实性**：历史AI/Tool消息重新出现在graph更新时，不作为新的工具执行、任务观察或PostToolUse；每轮统计只计本轮新请求和合法恢复。新AI合法复用call_id、未完成调用恢复、当前消息重复、无历史ID的旧适配器均需明确处理。回放以独立诊断事件携带身份，不能伪造原轮次。新工具事件说明requested/started/unknown，不用消息开始代替已执行证明。
2. **阶段约束**：从有效真实用户要求编译明确的“动作仅在阶段X执行”限制，保留来源。已知阶段匹配或更晚用户明确授权后可执行；一般“实现并运行新增测试”不扩展为受限制的公开复现。模型任务字段、文件、工具结果不能创建或解除授权。只对可识别的明确动作进行确定性拦截；复杂程序的行为不宣称被完整静态证明。约束投影保留未确定阶段与仍有效限制。
3. **验证执行**：现有run_command增加可选argv直接执行及expected_exit_code，旧command调用兼容；argv路径使用shell=False。argv权限判断与原Bash规则一致，审批绑定原始规范化参数。返回可信执行元数据、完整输出归档引用、实际返回码与预期匹配情况；stdout统计仍仅为观察，不自动证明测试或验收。超时、取消、输出上限、密钥脱敏、负向验证保持明确。echo/tail掩盖原过程的问题有实际回归。
4. **文件编辑预检**：完善读快照前置提示。一个工具批次对同一真实路径多次变更时，在审批/执行之前返回明确冲突，让模型合并一次patch或重新分批读取核对。不会静默重绑旧版本、修改已批准参数或越过保护。独立路径可继续并行，取消与未知副作用不重放。
5. **上下文效率**：在可恢复历史、已闭合的前轮工具交换上应用请求视图的主动缩减；使用实际输入估算与配置目标，保留当前真实用户工具链全部provider-required reasoning、有效要求及完整原检查点。没有恢复工具/完整归档时不破坏性缩减；输出观察与历史错误保留。提供环境/目标状态提示与交付证据自查指引，不自动创建目标或扩大写权限。
6. **测评隔离与交付说明**：提供固定源码副本的复测计划/离线检查，源码前后和当前开发状态分项；旧run、题目、评分、候选实现不改。记录本次实际变更、RED/GREEN和限制。文档行为正确性通过明确证据自查指导增强，不宣称一般语义验证器可以自动证明所有文案。

新增机制不得硬编码scanner答案、repro_cache_lifecycle路径、R1—R6评分或A—E产物。保留模型/max、原生40调用/256图步与未知副作用暂停；此次实现只跑离线回归，不把既有70/70改记成新版本实测成绩。

审查修正：更晚真实用户“现在执行目标”属于对该目标及明确参数的授权，阶段已知也无需特定解除口令；一般测试要求不构成目标授权。--dry-run授权不得扩大到--publish。原生结果由gate生成tool_result_id，历史/当前消息身份之外按结果身份去重及记录任务证据；旧适配器改写ID时的不可判定情况保留限制。
