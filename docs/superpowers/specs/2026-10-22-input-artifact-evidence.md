# 完整项目身份与交付产物证据

## 目标与授权范围

沿用用户的整个项目长任务可靠性审查目标：修复已复现的遗漏，保留完整任务要求、现有工作树和发布边界。实现为可逆的内部修复，不提交或推送，不调用真实模型 API。Factory 阶段已完成全量与安装模块验收，本阶段继续整体目标。

## 原生证据

1. 当前工作区按既有受保护名称过滤后有106149个普通文件、10073654300字节。input_fingerprint明确拒绝应用包中的符号链接。抽查的 Python 与 framework 链接目标均存在且在项目内。完整输入身份尚不可用。
2. 真实 VerificationService/TaskStore/GoalStore 执行成功构建，bundle/app.txt 列为生成物。通过后改写该文件，goal.update(complete)仍返回成功，Task进入completed。生成物被输入排除后，没有独立的当前产物证明。
3. 真实构建生成101个文件：返回记录101条，JSONL持久事件仅100条。再次验证因已有输出不属于前次生成物而拒绝。通用展示截断破坏了执行依据。
4. 验证命令要求 assets 空目录存在。通过后删除该目录，目标仍可完成。只覆盖普通文件不能代表项目命名空间。

原始探针分别在 /tmp/ignovate-input-scope-output-probe.log、/tmp/ignovate-generated-artifact-probe.log、/tmp/ignovate-generated-manifest-probe.log、/tmp/ignovate-empty-directory-proof-probe.log；均为本机临时/只读项目，无模型 API。

## 设计选择

采用明确类型的完整命名空间观察，以及独立、不可变的产物清单。输入观察包含目录存在性/权限、文件权限/内容、内部链接原文与目标状态。生成物的完整路径、类型和内容身份由私有清单保存，Task/Goal/JSONL只携带有界引用和明确的展示预览。

自动忽略 Gitignore、artifacts 或 dist 会隐去当前契约覆盖的输入；无界跟随外部链接则无法保证项目边界。因此保持既有输入范围和安全边界，完整描述内部链接图，项目外目标明确报告未知覆盖。文件工具继续使用其安全读写接口。

## 必须满足的契约

### 输入观察

- 目录、普通文件、链接使用不同的摘要域。目录增删、空目录变化、权限变化、普通文件与链接互换、链接目标变化都会改变身份。
- POSIX链接读取在已固定父目录下进行，链接的内部目标通过本次完整清单解析。读取内容时使用固定的原生普通文件句柄。内部缺失、循环和超过原生40跳限制的ELOOP作为明确状态描述；所有链接条目仍逐一覆盖，项目外、受保护范围或其他未知解析状态拒绝当前覆盖。Windows重解析点只在可验证的原生类型/句柄契约下支持，未知类型保持拒绝；模拟结果不能替代实机结论。
- 前后清单与版本、Git状态均一致才返回完整身份。取消、存储失败、扫描时限或容量耗尽不返回部分证明。沿用120秒、512MiB临时索引及受限摘要缓存；路径与元数据不因展示上限而省略。
- 验证执行前后的稳定性另绑定原生变化版本，内容改写后恢复不能证明检查了交付输入。允许输出成员变化的已有祖先目录须有原生移动、删除和属性变化见证，不能直接省略目录时钟以接受ABA替换。没有原生见证的平台保留严格版本检查；macOS原生验收不能替代Linux/Windows证据。
- 新身份有明确版本。旧格式仍能读取，重新核对时标为陈旧/未知并允许重新验证；用户要求、费用和历史不重置。

### 生成物权威清单

- 每个完整清单绑定项目、执行run、配置和完整条目数，记录所有实际生成条目的路径、类型、权限及内容/链接身份。目录与链接也属于条目。
- 使用私有目录、不可变内容摘要引用、至多1MiB片段、完整校验及最后原子发布清单。总清单有明确资源上限，初拟64MiB；超限明确失败，不能裁剪。读取与校验流式进行。清单引用不携带任意可读取路径。
- 原生生产者发布清单后，Task、Goal及事件才登记引用。Task与Goal使用各自固定存储边界；需要跨不同私有边界时先完整复制并核对内容，再在短状态事务中登记，持锁期间不做长扫描/复制。
- 预览明确标注条目总数与是否完整，不是后续执行、排除或验收的依据。101项、超过Task文档上限的元数据、多次构建及重启都从完整清单恢复。
- 首次已有输入与Git跟踪输入仍不能改称生成物。复用已有输出须有此前成功原生记录及完整清单；损坏或缺失清单不能扩大排除范围。
- 目录排除仅影响已知生成目录的身份条目，仍检查其后代。后来添加的未登记文件仍属于新输入，不能被目录前缀隐藏。

### 当前产物与消费者

- 输入一致与产物一致分别判断。通过后的产物改写、删除、权限或链接变化使原验收失效。记录不能只证明“输入没变”。
- 同一有所有者的后台观察取得当前输入与产物状态；返回后继续核对完整任务/目标/来源身份，保留现有取消和锁顺序契约。
- 更新全部权威判断：Task reconcile/delivery、Goal完成/自动验证复用、GUI工作控制/节点/人工决定、recap/export及反馈源判断。GUI共享观察的键必须包含完整清单身份，不能仅按相同预览路径复用。
- 旧记录若声明生成物却缺完整当前产物证明，显示陈旧/未知并要求重新验证。无生成物的有效旧记录也必须符合所用输入身份版本。
- 生成物枚举、清单读写和摘要都在owned worker执行，不把大目录同步遍历留在事件循环的参数求值中。

## 验证范围

必须原生覆盖上述四个复现、内部多跳/目录/缺失/循环链接、外部逃逸与置换竞态、生成物重启/清单损坏/发布中断、大于100条与大型元数据、产物改写后的Goal/Task/GUI/recap一致性，以及取消时控制通道可用。最后检查真实工作区身份、独立复核、完整Python/JS和外部安装模块。

本规范不把阶段通过等同于整个目标完成；长期存储回收、全面交付场景和原生Windows证据仍需后续审查。
