# 记忆目录、读取和预算设计

用户目标：先修会话隔离和截断提示，再做记忆目录、按需读取与统一预算，最后考虑自动记忆提取和向量数据库。

本次在已有记忆流程上实现上述基础能力；用户已授权实施前一轮分析给出的方向。保留当前工作区、未提交内容和编辑审批，直接在当前功能分支完成，不移动或提交用户已有改动。

## 行为与范围

1. 目标规则及状态更新工具只作用于已绑定该目标的会话；未绑定目标不能激活普通聊天或未指定会话的请求，也不能被这些会话修改。
2. 旧的三个 context 文件继续可读和可编辑。每层记录读取状态、文件版本、完整字符数与注入字符数；超限、UTF-8 错误、链接和目录错误可见，正常工作不因此停止。
3. 用户主题位于 `~/.nailong/memory/*.md`；项目主题位于 `.nailong/memory/*.md`；本地主题位于 `.nailong/memory.local/*.md`。逻辑 ID 为 `user|project|local/<文件名>.md`，其中 `context.md` 指向该层旧文件。不接受绝对路径、子目录、路径穿越或符号链接。
4. 主题元数据使用可选 YAML frontmatter 的 `description`；无 frontmatter 时使用文件名。目录只显示 ID、描述、大小、版本和读取状态，不自动注入主题正文。扫描最多 200 个主题，超过上限时明确报告。
5. `memory_list(scope="", offset=0, limit=20)` 分页查看目录；`memory_read(document, offset=0, limit=4000)` 按字符分页读取一个文档，返回完整长度、版本、截断状态和 next_offset。工具只能读，chat/plan 可用；init/review/subagent 保持原有权限范围。工具过滤仍有效。
6. `.nailong/settings.json` 和 settings.local.json 支持 `memory.max_tokens`（默认 4000，范围 512–16384）。三层旧文件摘要、目录、状态提示和 memory 工具输出使用同一个预算，而非各层各用一个上限。预算是保守估算：ASCII 字符 / 4 向上取整，非 ASCII 字符按 2 tokens 计；不是提供商精确计量。
7. 旧文件在预算内保持完整，超限时公平分配三层摘要并明确截断；分页可读到尾部。读取输出的 JSON 包装也计入预算。每次模型调用重新限制历史 memory 工具输出，保留较新的内容和文档/偏移指针，避免跨轮历史绕过预算；不修改持久会话记录。
8. 每轮运行创建核心和目录快照；已知文档的正文读取检查该版本，未列出 ID 在首次读取时绑定版本。运行中版本改变返回 changed，禁止拼接不同版本分页，下一轮刷新后可读新版本。`/memory` 和 `/context` 显示读取、截断、目录及预算情况，不把已截断的摘要误判为磁盘修改。doctor 检查主题目录和配置。

## 实施取舍

不迁移或重写现有 context 文件，主题文件由用户正常创建或通过现有审批后的文件工具维护。保留 SHA 检查和原子保存，不在本次扩展写入 API 或自动保存。

自动记忆提取在基础能力完成后评估：当前先保留显式编辑，避免把助手建议、临时状态和敏感信息自动固化。向量数据库暂不引入；本次提供确定性的目录与分页接口，后续只有主题规模及检索评估证明需要语义召回时再选择索引。该评估需记录理由和引入条件。

## 验收

- 原有会话隔离失败测试转绿；未绑定和其他会话均不收到目标规则。
- 截断、不可读和缺失有明确状态，尾部可分页取回，误报待 reload 修复。
- 主题正文不会出现在默认提示词中；真实 LangChain 工具调用能读到对应主题。
- 越界、链接、非 UTF-8、超大文件、非法参数被拒绝或报告；不会读取无关文件。
- 三层及目录总注入量、工具输出和带历史结果的后续模型输入遵守统一估算预算，中文内容也纳入计算；并发工具调用不能绕过预算。
- 修改记忆后下一轮能使用新版本；只读子代理与审查模式不获得用户主题工具。
- Textual、inline、plain 共享命令与结果；现有审批流程保持可用；全量本地测试通过。

自审：没有增加新模型、联网服务或依赖；阶段边界及预算语义明确，旧入口兼容，所有范围有对应验证。
