# 低开销会话、持续任务与跨会话协调设计

日期：2026-10-17（Asia/Shanghai）。状态：用户已授权实施，六项实现及全量测试已完成；最终审查记录见实施验收报告。

## 1. 目标与范围

落实本聊天确认的六项优化，按 P0 固定输入与用量解释、P1 自然持续任务与子任务预算接续、P2 跨会话协调与恢复推进。默认在普通会话理解并完成任务；只有已有相关会话或工作可以独立接续时，才调度其他会话。独立 dots 窗口是可选的后续界面，不是本次完成条件。

成功标准是四项用户可观察行为：简单交流固定输入明显下降；用户减少复制上下文、切换模式和输入“继续”；预算不足后保留成果并明确接续；交付有与当前要求、当前输入相符的验证证据。六项均须接入 CLI、GUI、无头模式的共享运行路径，不以仅新增类或测试替身代替功能。

本次不引入第二套模型运行时，不开放可写子 agent，不并行修改共享工作区，不重做现有会话地图，不要求用户手动准备完整任务规格。保留 /plan、/goal 和权限审批的原有入口及安全边界。

## 3. 方案选择

采用“普通会话的渐进能力与原生持续目标”：同一 agent 先理解需求，再按需加载能力，必要时协调已有会话。拒绝默认增加一个独立 dots agent，因为单任务会增加交接与重复上下文。也不采用仅缩短系统提示的补丁，因为完整工具与 Skill 目录仍会占据大量固定输入。

最终请求中的工具集合、提示规则、上下文统计、预算预留和工具执行准入必须一致。只隐藏 schema 而仍允许猜测调用，或只改统计而不改实际请求，均不满足设计。

## 4. P0：轻量输入与能力按需发现

### 4.1 默认会话与加载

普通 chat 初始只包含简洁的核心角色、真实权限边界、事实依据、用户暂停/取消优先，以及用于发现项目能力的短说明。不预载编码、委派、交付流程全文，不注入全部 Skill 目录、无关任务正文或项目背景。

无歧义的独立问候且不含任务指令时，初始请求不绑定工具；活跃任务及其暂停状态不被问候清除。其他普通交流使用一个有界能力发现入口，模型无需额外分类模型调用即可选择阅读、编辑、运行、记忆、Skills、任务控制或会话协调组。不能用仅识别几个问候词的分支代替一般交流的低开销路径。

发现目录由已注册工具和当前 allowed_tools/profile 的交集生成。返回条目和 schema 均有明确上限与分页。每次模型请求开始前冻结可执行集合；发现后的工具在下一模型请求才生效，同批次兄弟调用不能绕过加载。所有调用仍通过现有参数、版本、模式、阶段约束和审批执行门。

加载按会话持久化并绑定目录版本；目录变化、模式缩小、MCP 重连和分叉都重新求交集。新用户轮次按当前任务阶段选择工作集，避免加载一次后永久恢复全量。未完成工具交换所需契约必须保留直到闭合，不改写 checkpoint 中的真实用户要求。

### 4.2 Skills 与记忆

提供有界 Skill 搜索/分页发现，按名称或字面关键词选取，正文沿用 load_skill/read_skill_resource。用户明确指定的 Skill 可直接加载，不先要求全量目录。Skill 与工具内容仍是资料，不能授予新权限。

轻量交流不预载项目背景；用户显式指定的当前约束仍保留。工程任务按相关范围加载现有固定记忆，需结合历史任务的短指针恢复背景，不反复复制全文。已有显式模型、模式和 allowed_tools 选择具有优先权，轻量路由不能扩大它们。

### 4.3 验收

用同一模型、同一估算方法、空历史和包含 100 个无关 Skill 的夹具，对比当前全量 chat 与新路径。问候首次模型请求的固定输入估算至少降低 75%，且实际绑定工具数为 0、完整 Skill 目录为空；该阈值是工程验收目标，不是对提供商实际 tokens 的预先承诺。

还须覆盖一般交流→文件调查→修改验证→普通交流，以及跨轮恢复。未请求某个 Skill 时，新增 100 个无关 Skill 不得向普通交流请求增加完整目录或各条描述；其完整 schema 也不能换成文本再注入。真实经过 AgentService、create_agent、模型绑定与执行门记录请求；不得只测试分类函数。小窗口、工具名称猜测、同批发现与调用、目录变化、显式限制及中文混合指令有回归用例。

## 5. P0：可解释且不重复计数的用量

每轮展示：实际输入、实际输出、输入中缓存命中、合计、模型调用次数、会话累计，以及主/子/跨会话执行归属。缓存命中是输入子集，不重复相加。费用显示使用该次调用已有的价格快照；未知或缺失单独标记，不能显示为零。

分类估算展示系统、固定记忆、Skill 目录、已加载 Skills、工具 schema、工具结果、历史、任务投影、推理与封装。每次分类只计实际发送片段；分类和实际输入不能逐项强行对齐，也不能将所有模型调用的分类累加成“当前上下文”。

为模型请求、响应与 usage 分配稳定 call_id，绑定 turn_id、run_id、thread_id、task_id/revision 和可选 goal_id/dispatch_id。已有汇总事件与逐调用事件引用相同 call_id，去重后再累计。恢复、分叉和重复流式通知不能重复计费；分叉继承的历史不算该分支新发生的调用。

CLI /context、/cost，GUI 回合详情及轨迹，无头 JSON 均复用同一投影。GUI 同时可见单轮实际用量和估算明细，窄屏可展开；无需另开设置页才能诊断一次问候。

验收包括多次主调用、并发子调用、跨会话派发、缓存、缺失 usage、失败尝试、重复事件、分叉和恢复。用有固定已知 usage 的模型替身核对合计，再核对 UI/JSON 输出，不仅测试内部求和。

## 6. P1：普通会话自然进入持续任务

### 6.1 对话与任务说明

任务说明由 TaskStore 保存，包含目标、范围、约束、验收、未决问题和用户已确认的选择；阶段为澄清、方案、实施、验证、交付，沿用现有生命周期。每次要求变化形成修订，不用最新一句“继续”覆盖原始目标。

agent 对会显著改变目标、范围或验收的问题追问。只读调查可以帮助澄清；“我想做一个工具”“先解释方案”不授予写入或命令执行。小的可逆实现细节自行选择，无需每步重复确认。

提供结构化任务说明更新与启动持续执行入口，绑定最近真实用户消息、当前草稿和要求版本。用户明确提出实施请求时可直接启动；对已展示方案说“按这个做”可在同一会话启动。文件、Skill、模型文本及历史里的“已批准”不能启动执行。此处是产品运行时授权判断，不依赖模型自己填一个 approved=true。

### 6.2 共享目标驱动

CLI、GUI、无头均由共享流程消费启动意图，创建或恢复同一线程的 GoalStore 目标并调用 drive_goal。不要在模型工具处理函数中递归启动 drive_goal，也不要在同一项目锁内再次占用调度器。首次实施调用只发生一次，避免先普通 chat 实施、随后 goal 再重复实施。

允许模型提出可观察的验收和验证步骤，并通过已有类型化任务工具记录；自动测试类标准由实际验证绑定，人工验收保留用户确认。普通用户无需手写 /task accept、/task bind；命令继续作为可选入口。未知、失败、过期证据不能变为完成，整体交付沿用 delivery 判断。

等待用户回复时保存明确问题，不空转调用模型；新回复进入同一任务，更新要求后按原生控制判断恢复。用户暂停、取消及仅查询状态不自动恢复执行；预算上限不能通过自然语言入口重置绕过。

### 6.3 验收

端到端脚本覆盖“模糊想法→关键追问→用户澄清→实施授权→实际修改→验证失败→修复→验收完成”，全程同一线程且无需 slash 命令。另测直接明确实施、只出方案、问候、只问状态、修改目标、用户取消和待人工验收；未授权时副作用为零。没有证明每次自然语言判断正确的离线测试，不能写成模型成功率；提供不默认发网的实机验收脚本。

## 7. P1：分层预算与子任务接续

保留上下文窗口的硬限制和既有 GoalCostBudget 费用控制。新增非密钥运行配置，使用现有用户→项目→本地→CLI 优先级与严格类型校验；显示有效值与来源。子任务阶段额度、单次输出、收尾输出和并发数可配置，模型输出还受所选模型能力约束。

默认并发仍为 3，配置范围为 1–3；阶段 token 额度初始保持 30,000 以便比较，单次子调用默认输出提升为 4,096、收尾默认 1,024；这些是可调整的初始工程值，不宣称已实测最优。阶段及输出配置须为有限正整数，最终输出同时受模型及上下文余量限制。单个任务 description 不接受任意修改总额度。后续调参依据预算提前终止率、输出截断率和每个完成目标消耗。

阶段额度与目标累计费用不同：阶段停止先保存成果，可在目标余量内显式分配下一阶段；用户设置的目标上限必须在每次真实模型调用前检查。临时并发预留等待，不误判为永久耗尽；提供商用量未知时保留保守结算并暂停自动追加，不重试潜在已计费请求。

子任务结构化返回 completed/partial/budget_exhausted/failed/cancelled 等运行时状态、结论、原生工具证据引用、未完成项、停止原因和可接续引用。证据来自执行门实际观察，引用匹配不证明自然语言结论正确。字符串 worker 保留兼容，不能伪造证据。

接续记录保存在项目会话数据中，绑定项目、父任务/修订、子任务身份、输入版本、已读范围和归档引用。resume 使用原有身份与已有证据，不重新扫描已取得资料；输入版本变更时将相关观察标旧并定向重核。不能通过改写 prompt 或新建任务名规避拒绝。取消保留已有证据但不记录完成。

验收覆盖阶段停止→跨轮接续→完成、总费用上限、未知 usage、预留竞争、并发取消、记录失败、文件变化、恢复与分叉。每次调用结算一次，停止结果不再依赖文本前缀判断。

## 8. P2：按需跨会话协调

当前会话可调用有界会话/任务摘要查询、定向历史读取、接管、派发、查看结果和暂停/释放控制。只查当前工作区；普通问候不会加载会话列表。摘要先行，历史按引用分页取得，不将所有窗口全文搬到协调会话。

用户明确要求结合或接管相关会话，或已有目标的执行范围明确包含这些工作时，允许创建调度关系。读取历史不等于取得该会话执行权。已有会话继续关联自己的 TaskStore 权威，协调目标记录任务依赖与引用，不用 link_work_item 强行覆盖目标会话已有任务。共享同一任务的关联会话使用同一 task_id，不能重复计算完成数量。

派发契约包含唯一 request_id、协调目标、目标会话、任务/要求版本、阶段目标、允许范围、依赖、交付和费用归属。运行时核对目标可接续 checkpoint、任务当前修订及控制权，随后进入共享串行队列。已完成记录可复用，不能把同一会话历史中的失败工具再次自动执行。

抽出 GUI 与 CLI 共用的派发存储和串行驱动接口，GUIController 作为适配入口，CLI/无头在外层 turn 完成、释放项目执行占用后消费同一派发记录。工具只提交，不在持有项目锁的工具回调中等待目标会话完成。进程退出后待执行派发可恢复为待核对状态，无需依赖 GUI 进程内队列。

复用目标费用预算并增加调用归属；调度工作线程不反复 attach_thread 改变总目标归属或使已有验收失效。每个工作项的验证绑定其真实输入、运行与任务，协调目标的整体验收核对这些结果及集成验证。多个“完成”报告不能替代整体完成证据。

验收覆盖已有上下文接续、依赖接力、独立任务关联、用户干预、权限缩小、失效 checkpoint、跨项目拒绝、重复派发和含循环依赖的拒绝。CLI 和 GUI 使用同一派发状态，模拟模型与真实文件/验证执行证明功能接入。

## 9. P2：控制权、暂停与恢复

持久控制租约记录 owner、scope（目标或会话）、generation、状态和最后确认的执行边界；工具执行前与开始下一轮前核对。单会话同一时刻只有一个调度来源，用户最新指令优先。用户干预递增 generation/要求修订，使旧排队任务失效；运行中的副作用按现有取消和清理机制收束，后续调度重新读取状态。

全目标暂停停止后续派发并取消尚未开始的工作；单会话暂停不影响其他独立可执行工作。等待外部条件不占模型调用，恢复不能隐式解除用户暂停或原生审批。

每次派发经过 queued→admitted→running→completed/failed/cancelled/needs_reconciliation 的持久阶段，写入请求身份和原生 run_id。重启时 queued 且确定未开始的可恢复排队；admitted/running 或副作用结果缺失的先核对已有回执、文件版本和进程状态。无法证明未执行时进入 needs_reconciliation，不重放命令。

完成记录重复投递必须幂等，不能重复结算、修改文件或增加任务完成数。控制状态损坏或租约核对失败时保留未知并停止相关派发；其他任务不被误报完成。

## 10. 实施拆分与验证矩阵

实施顺序为 A→B→C→D→E→F，C/D 可以共享契约但均须完成后进入跨会话实现。各阶段独立写实施计划和运行针对性测试，全部阶段完成才算本目标达成。

| 阶段 | 责任与拟改入口 | 必须证明的行为 |
| --- | --- | --- |
| A 输入 | 新 capability/discovery 模块；agent.py、tools.py、prompts.py、skills.py、context_runtime.py、执行门 | 实际发送减少；按需扩展可执行；不绕过权限；恢复不残留越权加载 |
| B 用量 | usage/context 投影；AgentService、GUI 展示、CLI /context /cost、无头 JSON | 单轮/累计与实际/估算可区分；缓存及重复事件不重计 |
| C 自然目标 | task_requests、TaskStore、原生任务工具、共享 flows、CLI/GUI 入口 | 真实用户授权后同会话自动推进；关键澄清等待；验收自动记录并核对 |
| D 预算接续 | 子任务报告与接续存储、agents.py、budgets.py、运行配置 | 阶段额度可调；停止保存证据；接续不丢失；目标费用保护继续有效 |
| E 协调 | 共用派发存储/串行驱动、会话工具、TaskStore 引用、GUI/CLI 适配 | 已有会话接续、依赖派发、产物归属、目标级费用与整体验收 |
