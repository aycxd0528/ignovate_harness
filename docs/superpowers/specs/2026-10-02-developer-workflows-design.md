# 奶龙 Agent 开发工作流扩展设计

日期：2026-10-02
状态：已实施并完成本轮验收（2026-10-03）；详见 `docs/reviews/2026-10-02-developer-workflows-acceptance.md`
范围：用户选定的全部四项 P0 和四项 P1 功能

## 1. 目标与约束

让个人开发者在任意本地项目中使用奶龙 Agent 完成查看改动、审查、验证、继续会话和管理运行环境的完整流程。成功标准是下述功能在实际界面和持久化状态中成立，不能仅以命令出现在菜单中作为完成证据。

- 保留现有精确编辑、权限引擎、计划、目标、会话恢复、无头输出及本地 Skills。
- Textual、inline、plain 共用功能服务；展示、输入和审批由各自适配器负责。
- 中文界面延续克制的开发工具风；模型、累计用量和上下文状态继续固定在输入区域。
- 文件访问保持项目根目录和受保护路径边界。Skill、项目配置、Git 内容和模型输出都不能自行授予权限。
- 不修改密钥文件，不把密钥写入偏好、报告、事件、导出或诊断信息。
- 本轮不新增 daemon、RPC、MCP、插件市场、可写子代理、worktree 调度或操作系统沙箱。
- 当前工作区含大量既有未提交内容；实施时保留这些内容，按明确文件范围改动。

| 现状 | 代码位置 | 对设计的影响 |

| 固定记忆在运行时创建时加载；上下文统计主要计数历史文本 | `nailong/core/memory.py`、`agent_service.py:get_context_summary` | 支持重载并计入实际请求中的系统提示和工具定义 |

以上为静态读取结论；本设计阶段未重新运行测试，也未发送真实 API 请求。

## 3. 架构方案

| 方案 | 特点 | 成本 |
| --- | --- | --- |
| 共享功能服务，保留现有界面适配器（推荐） | 以当前 Controller、AgentService 和事件结构接入；队列拥有单一运行状态 | 需要梳理命令结果和取消接口 |
| 在各界面直接添加分支 | 改动容易从一个界面开始 | 命令、持久化和审批行为需维护三份 |
| 新建常驻后台服务 | 能支持退出终端后继续运行和远程控制 | 新增进程、协议与连接生命周期，超出本轮目标 |

推荐方案把参数解析、执行与显示分开：`CommandController` 返回结构化请求，共享 `CommandActions` 执行本地功能或创建模型任务，`SessionRunner` 串行驱动当前会话，界面消费统一事件并提供审批回调。

新增或扩展的职责边界：

| 模块 | 职责 |
| --- | --- |
| `nailong/core/git_changes.py` | 安全 Git 调用、选择差异、文件清单和覆盖范围 |
| `nailong/core/verification.py` | 验证配置、步骤执行、观察结果和持久证据 |
| `nailong/core/diagnostics.py` | 只读安装、配置、终端与运行状态检查 |
| `nailong/core/preferences.py` | 模型、主题、输出详略与 Skill 开关的有效配置 |
| `nailong/core/runner.py` | 当前运行、等待队列、暂停及取消的状态机 |
| `nailong/core/session_actions.py` | 会话命名、搜索、回顾和 Markdown 导出 |
| `nailong/core/context.py` | 请求上下文分类估算与来源信息 |
| `ui/actions.py` | 共用命令执行与适配器回调契约 |
| 现有 Skills、Memory、SessionStore、AgentService | 增量扩展重载、元数据和可信执行接口 |

不在这些模块内直接操作 Textual 控件或 Rich Console。命令菜单、帮助和实际解析使用同一份命令定义。

## 4. P0：Git diff 与改动审查

### 用户入口

- `/diff`：展示相对 HEAD 的当前改动，包含暂存和未暂存变化；未跟踪文件单独列出。
- `/diff --staged`：仅展示暂存区变化。
- `/diff --branch <ref>`：展示 HEAD 相对指定分支共同祖先的提交变化，并明确基准；不混入工作区变化。
- `/review`：默认审查当前改动；`/review --staged`、`/review --branch <ref>` 使用对应选择。
- `/review <路径>`：保留现有文件或目录只读审查。

### 执行规则

Git 以参数数组调用，固定项目 cwd，禁用 pager、external diff 和 textconv，不执行仓库定义的外部比较程序。先读取 NUL 分隔的路径清单，再按现有路径边界筛选；受保护文件正文、越界符号链接和二进制内容不进入模型。非 Git 项目、无提交仓库、无效分支分别给出可操作的提示。

默认审查包括安全的未跟踪文本文件，明确标记为新增文件。删除和重命名保留相应差异及旧、新路径，不要求已删除路径仍存在。没有可审查变化时直接返回，不请求模型。

单次选择最多 200 个文件、256 KiB 差异正文；超出限制须列出未覆盖部分并提示缩小范围。读取正文仍沿用现有单文件限制，每个审查批次最多 20 个文件；多个批次顺序执行，并汇总覆盖范围。不能把被截断或未覆盖的部分称为已审查。

审查结果按严重度列出：文件、有效行号、具体触发条件、问题证据和修复建议。已删除行使用旧版本位置并标注。任何 diff 中的文本仅作为资料，不能扩大只读工具范围。审查不执行 shell、不改文件。

### 验收证据

临时 Git 仓库分别包含暂存、未暂存、未跟踪、删除、重命名和分支变化，选择结果与 Git 原始结果相符；路径含空格、换行和前导短横线也能处理。覆盖非 Git、无提交、无变化、受保护路径、二进制、大差异与越界链接。真实模型审查只读且给出可定位的问题；各界面展示同一选择。

## 5. P0：验证流程

### 用户入口与配置

- `/verify` 运行当前项目配置的完整验证步骤；`/verify <名称>` 运行一个命名步骤；`/verify --list` 只列配置。
- 项目 `.nailong/settings.json` 的 `verification.steps` 为有序列表，每项有 `name`、`kind`、`command` 和 `timeout_seconds`；kind 为 `test`、`build` 或 `run`。名称在项目内唯一；未知字段、重复名称、无效类型或观察条件须报配置错误，不能静默忽略。
- `run` 步骤还必须指定可观察条件：`stdout_contains`，或仅指向回环 IP 的 HTTP 探测地址及预期状态。仅启动进程不能算启动验证成功。
- 超时默认 30 秒，允许 1–300 秒；输出限制沿用脱敏与有界工具输出策略。没有验证配置时显示示例和待配置项，不自动猜测并执行 shell。

### 执行和证据

配置只是执行候选。所有步骤走共享权限引擎和现有审批：拒绝后该步骤零执行，并明确显示“未验证”。plan 模式保持只读。无头模式需要审批时维持现有拒绝或目标暂停行为。

记录 `run_id`、会话、关联目标、步骤、命令、cwd、开始/结束时间、退出码、超时、观察结果及脱敏输出。证据保存在项目隔离的数据目录中，界面与无头事件引用同一记录。模型不能传入“成功证据”替代真实执行。

test/build 要求退出码 0 且未超时；run 要求进程实际启动并满足观察条件，之后清理验证所创建的进程组。因正常清理而终止的服务进程不会被误判为启动失败，但该结果不能伪装成普通命令退出码 0。

完整验证全部通过后才允许作为 `/goal` 的验证完成证据；命名步骤部分通过须标记为部分验证。关联目标的步骤必须全部结束后才提交整次成功证据，不能由第一个成功命令提前放行完成。

验证记录保留执行前后的安全项目文件内容摘要、配置摘要和 Git HEAD/暂存状态。排除受保护目录、`.nailong/exports/` 和步骤显式声明的 `generated_paths`；生成物只能是项目内相对路径，不允许绝对路径、`..` 或越界链接，不能匹配任何已跟踪文件、本次 diff 中的新增输入、配置或记忆文件。验证运行前后输入摘要不同，该次验证无效；运行后首次生成的声明生成物可以忽略。完成目标前比较执行后的摘要，任何未排除的外部变更都使证据失效；摘要无法完整取得时不能声称证据仍有效。工具文件修改、目标会话变化或恢复继续按现有规则使旧证据失效。

可附带 verify Skill 解释结果和提出下一步，但执行、审批与证据归核心服务管理。

### 验收证据

使用本地成功、失败、超时、输出匹配和实际 HTTP 服务五类进程验证；拒绝后无进程和文件副作用。覆盖取消时的进程清理、证据保存、部分通过不能完成目标、修改后证据失效，以及 json/stream-json 可解析结果。

## 6. P0：诊断与状态

- `/doctor` 与 `nailong doctor`：检查 Python 3.11 要求、当前解释器/虚拟环境、requirements 中依赖、Git、可选 rg、启动命令 PATH、JSON/YAML 配置、Skill 诊断、记忆文件可读性与 TTY/编码/UI 兼容性。
- 同时支持 `python main.py doctor`；项目提供可安装的 `nailong` 命令入口，使用当前工作目录作为默认工作项目，不改变已有启动参数。
- 必须能在 API 配置缺失或损坏时运行诊断，不能先因 Agent 启动失败退出。
- 默认不联网、不调用模型、不安装依赖、不自动修改配置；输出每项的通过、提示或失败和修复命令。
- `/status` 显示项目、会话名称/ID、当前模型、API 主机、权限模式、UI、当前运行/队列、目标状态、累计用量、费用可估算性与统计完整性。
- 诊断、状态和正常启动共用环境判定函数，避免“诊断支持但启动拒绝”的分歧。未知用量明确显示未知，不显示 0；敏感 URL 信息去除认证和查询参数。

验收：缺失 API 配置、依赖不全、损坏配置、非 TTY、NO_COLOR 和未知价格均得到明确结果；诊断可离线启动。生成中 `/status` 可立即读取，且不新增模型调用。

## 7. P0：Skills 管理与热重载

- `/reload-skills` 原子重建有效目录，报告新增、修改、移除与无效项；同步刷新菜单、模型目录提示和下一次工具调用。
- `/skills` 列表显示名称、项目/用户来源、启用状态；`/skills show <名称>` 查看完整说明，`/skills enable|disable <名称>` 管理项目偏好。
- 新增诊断项包括文件路径及原因：缺 frontmatter、名称不匹配、描述无效、大小超限、不可读或越界链接。不能静默丢弃而没有解释。
- 项目覆盖用户的现有优先级保持一致；禁用的同名项目 Skill 不能意外回退到用户版本。
- 热重载在当前调用结束后的安全边界生效。已加载进对话的旧说明不会静默改写历史；显示其来源版本，并在下一次显式使用时加载新版。
- Skill 说明、资源或启用动作不能授权命令，也不自动运行其中的脚本。

验收：运行中新增、修改、删除 Skill 后无需重启即可按新版目录使用；无效项有原因；禁用项不会被模型继续发现或加载；重启保留开关，权限不发生变化。

## 8. P1：输入与运行控制

会话 runner 的状态为 idle、running、cancelling、paused；最多保存 10 条等待任务，超限保留用户输入并提示。Enter 在生成期间把任务加入队列，界面显示序号、简短内容与等待状态，完成后按序执行。

- `/queue` 查看；`/queue remove <序号>` 移除；`/queue clear` 清空；`/queue resume` 恢复暂停队列。
- 任务加入队列时绑定项目和会话；执行时按队列顺序取得当时有效的模型、Skill 目录、记忆和偏好，不把旧模型配置冻结在排队消息上。模型或偏好变更命令也进入同一队列，当前调用继续使用开始时的配置。切换项目、恢复/清空会话需先处理或显式清空等待任务，不能将它们转移到另一会话。
- `/stop` 或运行中的第一次 Ctrl+C 取消当前生成，关闭流、清理该运行持有的进程、暂停目标并保存已发生用量。取消后保留会话和等待任务，队列进入 paused，不能自动开始下一条。
- 空闲时 Ctrl+C 清空当前输入；输入为空时显示退出提示，退出使用 `/exit`。结束运行不会分配新会话 ID。
- `/status`、`/cost`、`/context`、`/queue` 和 `/stop` 在运行期间立即生效；模型任务和会改变运行上下文的命令按安全边界串行处理。
- 工具行默认仅显示名称、路径、结果和耗时；Textual 可以展开详情，inline/plain 用 `/tools [调用序号]` 查看脱敏、有界的详情。恢复后可查看已保存的安全详情，不恢复未经筛选的原始参数。
- 审批等待仍由审批输入拥有焦点，Ctrl+C 拒绝当前审批并取消运行，不能批准待执行操作。

验收：真实生成期间追加两个任务，按序仅执行一次；取消保留 ID、历史、费用和待执行项；审批中停止零执行；工具展开不重复生成最终回答。覆盖 Textual、inline 和 plain 的输入路径。

## 9. P1：会话命名、搜索、回顾与导出

- `/rename <名称>` 为当前会话保存名称，去掉控制字符，限制 80 个可见字符；标题栏和恢复列表显示名称。命名数据独立于会被 rewind 截断的对话事件。
- `/sessions [关键词]` 按名称、ID、历史用户提问和安全摘要搜索，保留明确会话 ID；搜索结果显示的序号必须对应这一次结果，不复用未筛选列表的序号。
- `/recap` 汇总完成事项、待办和已验证/未验证项。目标、执行记录和验证记录为证据；需要模型概括时使用无工具的单独调用、记录真实费用，不更改已保存对话。
- `/export [项目内路径]` 导出 Markdown，包括名称、项目、对话、用量和验证摘要；默认写入 `.nailong/exports/<会话>-<时间>.md`。原始工具 JSON 和密钥不导出。覆盖现有文件前显示 diff 并走现有审批。
- 旧会话无元数据时正常列出和恢复；损坏单条记录不得导致整个会话列表崩溃。

验收：跨进程保持名称和搜索结果，名称控制字符被清理；回顾不会把失败操作称为完成；导出可读且边界/脱敏有效，拒绝覆盖时原文件不变。

## 10. P1：模型、主题和偏好

启动时统一偏好来源：内置默认值 → 用户 `~/.nailong/preferences.json` → 项目 `.nailong/settings.json` → 项目 `.nailong/settings.local.json` → 本次 CLI 显式参数。会话中显式 `/model`、`/theme` 或 `/config set` 产生的本次覆盖优先于启动值；下一次启动仍按上述来源顺序解析。合并时保留已有 permissions、pricing、hooks 等字段；写入采用原子替换和文件权限 0600，写入前校验目标与父目录未被符号链接重定向。

- `/model` 列出有效模型配置；`/model <名称>` 切换已配置 model ID，下一次请求生效，保留检查点和会话 ID。
- `models` 是名称到 `{model: <model ID>}` 的映射；启动环境中的现有模型始终作为 `default` 条目可选。只读取用户及项目的非敏感模型声明；API key、base URL 和环境变量引用不作为可写模型字段。
- 本轮模型配置沿用现有 DeepSeek 兼容提供商、API 基址和认证来源；模型切换不能由项目文件把现有密钥发送到另一个主机。无需实现新的提供商 SDK。
- `/theme dark|light|ansi` 切换主题；所有用户、助手、工具、diff、审批和 Markdown 颜色来自语义主题，NO_COLOR 和 ASCII 回退继续有效。
- `/config` 显示非敏感有效值和来源；`/config set <键> <值>` 设置 `model`、`theme`、`output_style`，输出详略为 concise、normal、detailed。
- 命令设置默认保存至项目 settings.local；`--global` 保存用户偏好。显式命令所要求的偏好变更直接写入；不额外弹出模型工具审批。损坏配置给出错误，不覆盖或静默重置。
- 模型变更同步刷新 RuntimeFactory、CostEstimator、上下文窗口、状态栏和后续验证/目标费用保护。每次调用保存实际 model、提供商主机、输入/缓存/输出用量和当时有效的单价快照与来源；旧记录缺少模型或单价时标记无法完整追溯，不能用当前单价伪造历史准确费用。价格必须为有限非负数。切换到未知价格模型后仍允许普通对话，但目标模式暂停并要求配置价格，不能放行无价格保护的下一次目标调用。
- 输出详略作用于后续回答指引和工具详情默认展开度，不能删减审查证据、失败原因或验证状态。

验收：同一会话切换两个已配置模型后请求参数正确，费用按各次模型累计；重新启动与不同 UI 得到相同偏好。深浅主题在 100×32 和 80×24 下可读，NO_COLOR 无颜色转义。CLI 显式参数优先级有可观察证据。

## 11. P1：记忆与上下文明细

- `/memory` 显示 user、project、local 三层来源、路径、大小和当前加载状态；`/memory show <层>` 查看，`/memory edit <层>` 编辑，`/memory reload` 重载。
- 编辑在 Textual 使用编辑框，inline/plain 用参数数组调用 `$EDITOR` 编辑权限 0600 的临时副本；不直接把原文件交给编辑器。没有编辑器时提供原文件路径与手动编辑/重载说明，不声称已经编辑。编辑结果先显示 diff，再通过现有审批应用；取消不写入。保存前校验原文件内容摘要及链接边界，编辑期间被其他进程修改时拒绝覆盖并展示冲突。
- user 层仅允许明确选择的 `~/.nailong/context.md`；project/local 严格限制到对应项目文件，校验符号链接，不能借层名称读取任意用户文件。
- 重载仅刷新下一次请求中的固定记忆，不删改检查点、会话和历史费用。运行中变更等待安全边界。
- `/context` 分类显示基础系统提示、固定记忆/批准计划、Skill 目录与已加载说明、工具定义、工具结果、其余对话的估算 tokens，以及合计、模型窗口、压缩阈值和最近一次主模型实际输入量。
- 分类互斥，合计等于分类总和，不能把 system prompt 与其中的记忆重复计入。明确标为字符估算，不能声称等于提供商 tokenizer。实际输入未知时显示未知；子代理用量不替换主上下文统计。

验收：编辑拒绝/取消不写入，重载后下一次模型请求含新版记忆；各分类与实际构造请求的来源相符，工具 schema 和固定系统信息不遗漏；compact 后分类仍一致。

## 12. 安全、兼容和发布证据

实施首先恢复并确认主、子模型调用的预算/用量中间件接线；取消、超时、缺 usage、重试和模型切换都必须保留已发生费用或未知预留，不能把未知标为完整统计。

验证分四层留证：

1. 核心服务：隔离临时项目、Git 仓库、配置和会话目录，验证每项明确行为及失败条件。
2. 跨界面：三个交互适配器共享解析与执行结果；运行控制、审批、显示和恢复路径分别检查。
3. 实际运行：真实 CLI 子进程、实际本地验证进程及 Textual 渲染，不能只调用格式化辅助函数。
4. API：使用既有授权和当前配置做有界调用，核对真实模型参数、工具调用与提供商 usage；报告请求失败及未知费用，不将超时作为通过。

完成审计需逐项覆盖上述八个功能组及各自验收，维护需求—实现—证据对照表。任何缺失、仅静态实现或未验证项均保持未完成；既有回归失败必须说明并处理与本目标相关的失败。

## 13. 实施拆分

本轮总体目标不缩减，实施计划按可独立验收的子项目组织：

1. 可信运行基础与共享命令接口：预算/usage 接线、模型标记、统一执行结果。

每个子项目在共享接口明确后再落到实施步骤；不以只完成 P0 作为总体目标完成。

## 14. 设计自查修订

静态核对当前命令定义、价格估算、会话用量事件和目标恢复规则后，补充以下约束，尚未将其实现或验证为产品行为：

- 排队任务绑定项目/会话，模型和偏好按队列顺序在执行时生效，避免状态栏与实际请求模型不一致。
- 会话内显式偏好覆盖启动 CLI 值；下一次启动恢复正常来源优先级。
- 调用记录保留单价快照；配置价格变化不追溯重算历史，未知价格和非有限值不能绕过目标费用保护。
- 外部编辑器操作临时副本，批准保存前校验原文件，保证取消及并发修改不会被覆盖。
- 生成物排除不能匹配已跟踪文件或本次改动输入，验证过程自己修改输入也会使证据无效。
