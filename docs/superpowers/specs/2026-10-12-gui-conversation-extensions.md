# GUI 对话与插件细化

用户本轮 9 项要求及四张截图为设计依据。在现有源码工作台上实现，继续使用 Ignovate 的原生模型、工具、分支、Skills、MCP 与权限引擎。

- 输入区参照图一：紧凑输入，左侧文件引用与权限，右侧推理选择和发送/停止；保持蓝色品牌与黑白灰主题。保留已有名称提示和推理等级保存，细化滑块为蓝色填充、离散刻度、滑动圆点与重置默认。
- 对话参照图二：用户输入靠右的灰色气泡；模型正文靠左，状态与处理时间置于正文上方，消息时间/用量/真实动作置于下方。保留 Markdown 与引用追问、分叉、编辑、重新生成。
- 新会话在首条用户请求入队时生成标题，最多 80 个字符；不使用模型回答。用户手动标题和分叉标题不自动覆盖。未来导入的未命名 CLI 会话也使用首条用户输入。
- 实时工具状态采用原生 `tool_start/tool_end/status`，按 call_id 更新，显示命令或文件预览及结果。等待审批、失败、中断与重载均须反映真实状态；不伪造命令输出。
- 任务时间从实际执行开始计算，排队单独显示；完成后冻结并保存，重新加载仍可显示。旧日志按其时间戳恢复，缺少数据时显示未知。
- 详情栏展示实际写入/编辑文件、命令结果和验证等产物，保留来源、工具过程和用量，不重复展示模型回答。文件预览标明当前共享工作区。
- 插件页参照图四的列表/开关布局，先接入原生 Skills 和 MCP：刷新、安装本地 Skill、项目级启停、添加/编辑 MCP 声明、连接/断开及移除。连接/安装动作由用户主动触发；列出插件不启动服务或调用模型。MCP 凭据仍仅接受环境变量引用；忙碌时禁止修改；插件记录随项目隔离。
- 沿用实际源码路径，保留当前未提交用户工作，不新建隔离副本或提交混合变更。测试使用临时项目和本地假模型/测试 MCP 服务。

验收：首输入标题稳定、手动标题保留；长草稿、窄窗口、明暗主题和键盘可操作；工具状态/耗时重载后保持；详情栏无回答重复；插件真实保存并被下一原生回合使用，错误配置不破坏旧值。
