# 跨架构对比测试报告

> **一份报告 = 一个 agent 的一次完整运行（R1–R6）。**
> 同模型组在不同 agent 架构上运行同一道难题，用同一套探针与 Rubrics 记录表现；Codex＋不同模型若纳入，单列为产品参考组。
>
> 目的：记录表现、定位失败过程，并形成有证据的原因假设。
> 归因原则：全部失败或部分失败仅描述观察分布，不能单独判定模型或脚手架原因。记录日志证据、混杂因素及受控复跑结果；证据不足时保留为未核实假设。

填写提示：`【填】` 标记处需要你补内容；表格中留空的单元格全部需要填。

- [ ] 核对对应工具是否注册、允许调用、实际启动及返回有效结果；区分模型选择、权限拒绝、服务不可用、参数/schema 错误和协议适配错误。工具存在或缺失本身不完成原因判定。
- [ ] 记录可能的混杂因素：任务表述与验收假设、起始文件/依赖/网络等环境、运行顺序和人工介入、随机性、模型版本/服务来源/采样与推理配置、上下文和费用上限、回退模型、工具协议与适配差异。全部失败可能来自共同条件，部分失败也可能来自这些差异。
- [ ] 按比较组别整理已有重复运行。多个架构出现同一失败只支持“可能存在共同因素”的假设；同模型组与 Codex 异模型参考组的失败分布不能合并用于模型因果归因。
- [ ] 若在既定任务范围内安排受控复跑，先写明假设、保持不变的条件、唯一有意改变的因素及预期可区分的结果，再记录实际结果。复用原任务与 Rubrics，不自动增加实验范围；未复跑、结果不稳定或同时改变多个因素时，不写成已确认因果结论。

结论应限定在所记录的任务、环境、版本与配置内。Rubrics 的类别与评分描述用于记录表现，不替代原因证据；允许多个机制共同作用或暂不归因。
